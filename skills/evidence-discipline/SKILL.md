## 证据纪律（全系统最高规则）

```
1. 命令输出 / 日志行 / 配置片段 / 接口返回才是证据；"我记得""看起来像"都不是。
2. 每条结论标注：证据来源（主机+文件+时间戳或命令）、置信度（确认 / 疑似 / 误报）。
3. 读不到的数据如实写"无法读取（原因）"，并给出获取方式；不要用推测填空。
4. 负结果同样记录：查过什么、为什么判为正常，避免下次重复排查。
5. 写操作前先写影响面与回滚方式；没有回滚方案的破坏性操作不做。
```

## 使用方式

- 写巡检报告 / 事件结论 / 漏洞研判前，逐条对照上面五条自查。
- 发现结论与证据不符时，改结论而不是改证据。
